Key idea

How to work today

Every task follows the same three steps: look at the data without deciding anything yet; turn what you noticed into a question that has an answer; then decide what it means for the colleague's model, and write that down. The last step is the one people skip. A page full of tables and empty of decisions will not help you later.

Code is shown in R and in Python; pick the tab you prefer and the page remembers it. You do not have to write any code, and you do not have to understand every symbol. Read the line in English under each code box, press Run, and look at what comes out. Work with the person next to you.

Part 0 · Opening the data

With the class · about 12 minutes

Key idea

A table of data is called a data frame in both R and Python, and almost everyone calls their first one df. One row per record, one column per field.

Why read every value as text? Left alone, R and Python guess what each column contains. They are quite good at guessing, and that is the problem: they will quietly turn "01" into the number 1, and they will each decide for you which words mean "missing". Today we want to see the data as it was actually typed, so we read everything as text and decide later, on purpose.

Part 1 · Asking a single column a question

With the class · about 13 minutes

Key idea

The single most useful thing you can do to a column is count what is in it: how many times each different value appears. In R that is table(); in Python, value_counts(). Then compare the list with what the data dictionary says the column should contain. When the values do not match what the dictionary promised, that is called a conformance problem.

Before you answer

You probably expected two values. The dictionary says sex is a choice between two options (M, Male | F, Female). The data contain seven different spellings. Somewhere between the form and this export, values were typed or pasted without being checked.

Why it matters: any code that keeps only the rows where sex is "F" silently drops the patients recorded as female or 2. Not with an error. Silently.

Your turn 2

Count a different column

Pick a column and count its values. Compare what you see with what the data dictionary says the column should contain. Good ones to try: consent_type, outcome, smoking_status, ethnic_category, site_code.

Before you answer

99, 999, Z and blank

Count ethnic_category and you will see the codes 99 and 999, a Z, and some blanks. These are not all the same thing. In the NHS Data Dictionary, 99 is a real code meaning not known (nobody asked, or the answer was not recorded) and Z means not stated (the person was asked and chose not to say). 999 is not an NHS code at all: it is somebody's shorthand for "I didn't fill this in". A blank could be any of these.

Task 2 · FAIR assessment and first mapping

In pairs · about 20 minutes

Key idea

FAIR: four questions about whether a dataset can be reused

FAIR (Wilkinson et al., 2016) is a checklist for whether other people, and other people's computers, can make use of a dataset. Two things it does not mean: FAIR is not open (a dataset locked inside a Trusted Research Environment can be fully FAIR), and FAIR is not about whether the file looks tidy to you.

LetterThe questionFor a clinical study dataset, that means…
FindableCould someone discover that this dataset exists?It has a permanent identifier (not just a filename), a description, and is listed in a catalogue
AccessibleIs there a defined way to ask for it and receive it?An access process, a TRE or an API, rather than a spreadsheet attached to an email
InteroperableCould it be combined with other data without a person translating it?Fields use shared code systems (SNOMED CT, ICD-10, dm+d, LOINC) rather than local codes or free text
ReusableCould someone else use it correctly?The licence, the provenance and the processing history are written down, and the structure follows a recognised model

Score NORTHSTAR as you received it: the export, the data dictionary, the scenario, nothing else. 2 met · 1 partly · 0 not met · ? cannot tell. One line of justification each, always.

Key idea

Mapping: saying the same thing in a shared language

Hospitals write the same fact in different words. A terminology is an agreed list of codes so that "OSA on CPAP" at one site and "sleep apnoea, uses CPAP" at another become the same code. The lecture gave you four terminologies and one common data model:

StandardWhat it codesWhere you meet it in England
SNOMED CTClinical findings, disorders, procedures and much elseThe mandated terminology for NHS clinical records
ICD-10Diagnoses, for statistics and paymentHospital Episode Statistics, death certificates
dm+dMedicines and devicesPrescribing systems, GP records, dispensing
LOINCLaboratory tests and observations (what was measured; the value and unit sit alongside)International; used by OMOP for measurements. NHS pathology in England is moving to SNOMED CT, so you will meet both
OMOP CDMNot a terminology: a shared table structure that coded data is placed into, so analysis code can be reused across sitesResearch databases; the target for a lot of UK data engineering work

You will not be able to map everything, and you are not expected to look up actual codes today: concept names in words are enough. Where a value cannot be mapped, write down why. That is the finding.
